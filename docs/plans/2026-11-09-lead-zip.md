# Lead form ZIP code (Nov 9 2026)

## What
The lead form gets a required ZIP code box next to City. The server saves it, uses it for the state, and passes it to
RoofLink through the n8n webhook. A missing or invalid ZIP never rejects or fails a lead on the server.

## Why
RoofLink's job API rejected a test job with HTTP 400:

```
{"first_name":["This field is required."],"state":["This field is required."],"zipcode":["This field is required."],"source":["This field is required."]}
```

The form had no ZIP and the job body kept the name under `customer`, not at the top level. The RoofLink key and
endpoint are fine. The owner chose to add a required ZIP box.

## Files
- `src/lib/contact-check.ts`: `checkZip` (5 digits or ZIP+4), `stateFromZip` (600-629 IL, 630-658 MO), `zip` field error.
- `src/lib/illinois-guard.ts`: `looksIllinois` also reads `zip` (600xx-629xx means Illinois).
- `src/components/lead-form.tsx`: required ZIP input (same inline error handling as phone and email); City stays optional.
- `src/app/api/lead/route.ts`: parses ZIP, stores `zip`, `LEAD ZIP CHECK` log (result only), team email line, retry set
  `OPTIONAL_COLUMNS` includes `zip`, RoofLink job top-level `first_name`, `last_name`, `state`, `zipcode`, `source`,
  `phone`, `email`; webhook gets `zip`, `zipcode` and the improved `state`.
- `src/app/privacy/page.tsx`: lists ZIP code.
- `README.md`: ZIP column SQL and the webhook fields.
- Tests: `tests/contact-check.test.mjs`, `tests/lead-route.test.mjs`, `e2e/lead-form*.spec.ts`.

## SQL (run in Supabase SQL Editor)
```sql
alter table public.leads add column if not exists zip text;
NOTIFY pgrst, 'reload schema';
```
Until it runs, the insert retries without `zip` (PGRST204), so no lead is lost.

## Rollout

   `/roof_link_endpoints/api/light/jobs/`.
4. Send one test lead (Missouri ZIP 63101, then Illinois ZIP 62298) and confirm RoofLink accepts the job.
